在实验 02 中，我们只需要盯住一根连杆。来到机械臂，四个关节都在追踪自己的目标，而它们共同决定末端的位置。一个关节的微小变化，可能让夹爪走出一段明显的轨迹。

[打开实验 05 · 多关节控制](/lab/?example=arm-control#experiment)。入口动画中的线框表示目标、实体表示响应，是帮助辨认两者的动作示意；进入实验后，关节角度与曲线来自实际 MuJoCo 仿真。

## 四个目标，不等于一个末端位置指令

当前实验控制底座、肩部、肘部和腕部的目标角度。面板中每个滑块旁同时显示实际角度，图表则聚焦肩部，方便看清瞬态过程。

这里没有把“末端坐标”反解成关节角度。改变肩部时，前臂、腕部与夹爪一起转动；改变腕部时，上臂的位置不会因此在运动学上被重新定义。关节之间还通过质量和惯性发生动力学耦合，所以实际运动需要时间。

## PD 的两项依然在场

本站的四个旋转关节都使用位置执行器，默认 Kp = 120、Kd = 14。单位传动关系下，执行器请求的力矩为：

```text
τ = Kp · (q_target − q) − Kd · q̇
```

P 项纠正位置误差，D 项抑制运动速度。面板统一调整四个旋转关节的这两个参数，夹指执行器保持自己的参数。关节的被动阻尼也仍存在，因此“把 Kd 设成 0”并不等于“系统没有任何耗散”。

MuJoCo 的 `position` 执行器使用 `kp` 和 `kv` 表示这两个反馈系数，详见[位置执行器说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html#actuator-position)。网页使用控制中常见的名称 Kd 表示速度反馈。

## 用一次可重复的切换比较

1. 重置实验，保持重力补偿开启、Kp = 120、Kd = 14。
2. 点击“侧向姿态”，观察肩部目标曲线先改变，实际角度随后靠近。
3. 回到初始姿态，把 Kd 降低，再次切换到侧向姿态。比较超调与稳定所需时间，不只看末端走得快不快。
4. 恢复参数，关闭重力补偿，等待稳定后查看位置误差。
5. 改变肩部目标，留意腕部没有单独接到新目标时，夹爪仍会随整条链运动。

## 为什么增益大也可能有误差

静止时速度接近零，D 项几乎不提供维持力矩。关闭重力补偿后，P 项往往需要保留一点误差才能平衡重力。更高的 Kp 可以减小偏差，但还要受力矩上限、关节限位和接触约束影响。

这只机械臂的旋转执行器限制为 ±90 N·m；目标也会限制在对应关节范围内。它不是一个任意目标都能瞬间到达的几何摆件。重力补偿只作用于机械臂刚体，独立方块始终受到重力。

## 代码写的是目标，仿真算的是结果

以下片段在已经加载 `arm.xml`、创建 `data` 后使用。它修改执行器目标和增益，再执行一步仿真，而没有直接覆盖关节位置：

```python
servo = mujoco.mj_name2id(
    model, mujoco.mjtObj.mjOBJ_ACTUATOR, "shoulder_servo"
)
data.ctrl[servo] = 0.7  # rad
model.actuator_gainprm[servo, 0] = 120
model.actuator_biasprm[servo, 1] = -120
model.actuator_biasprm[servo, 2] = -14
mujoco.mj_step(model, data)
```

下载[完整运行包](/examples/arm-lab.zip)，执行 `python arm.py --example control --kp 120 --kd 14`。程序会在两组姿态间切换；加入 `--no-gravity-comp` 可以比较重力偏差。

下一篇[位姿与传感器](/journal/arm-sensors/)会把这些运动读成数值。先确认关节是否接近目标，再讨论末端是否到了期待的位置，这两个问题值得分别回答。
